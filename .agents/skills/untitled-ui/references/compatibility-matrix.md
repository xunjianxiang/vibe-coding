# Untitled UI 兼容矩阵

在现有项目运行 `init`、`add` 或 `example` 前读取。按可观察事实逐项分类，不根据依赖名称或目录外观猜测。

| 条件 | 直接集成 | 有限修复 | 仅参考 |
| --- | --- | --- | --- |
| 框架 | 根目录有有效 Next.js 或 Vite 配置，且使用 React | 配置缺失，但依赖、入口和脚本能证明是 Next.js 或 React + Vite | React-only、CRA、Vue、Angular、Svelte、服务端模板或无法确认 |
| Node.js | 20 或更高 | 可在不影响运行与部署基线时升级到 20+ | 当前运行或部署不能升级 |
| 组件库版本 | `components.json` 为 7/8，或新接入采用当前默认 8 | 声明缺失但可创建，或无需主版本升级即可修正 | 声明冲突、版本无法确定或必须迁移主版本 |
| TypeScript 与别名 | 有可解析 tsconfig 和有效路径别名 | 可补充配置且不改变模块边界 | 增加别名会影响现有构建解析 |
| Tailwind | Tailwind 4，框架插件与入口正确 | 可有限补齐或升级且不破坏样式/构建 | 会破坏现有样式、插件链或构建流程 |
| 样式入口 | 能定位全局样式、theme 和 typography | 可新增并明确接入 | 多入口或运行时注入使接管边界不明 |
| 包管理器 | 唯一 lockfile 与实际工具一致 | 可清理错误 lockfile 且不改变 workspace 策略 | 多 lockfile、workspace 策略或安装命令无法确定 |
| 依赖 | 预检无未解决冲突 | 受支持的小版本调整可解决 | 需强制安装、`--legacy-peer-deps` 或主版本升级 |
| 接管边界 | 明确到单个应用或前端 package | 可在当前功能前明确 | 只能靠长期双运行时或不受控全仓替换 |

## 判定

- 所有条件都在“直接集成”列，才使用直接集成模式。
- 出现“有限修复”时，列出准确文件、依赖和影响。修复不改变框架、路由、数据/认证边界、部署基线和组件库主版本，不覆盖或删除用户文件，也不扩大任务范围时，才属于有限修复。
- 任一条件落入“仅参考”，不要对目标项目运行 Untitled UI 写命令。
- 信息互相冲突或无法确认时，按“仅参考”处理，直到通过只读检查获得证据。

当前 CLI 没有可替代上述检查的 `doctor` 命令。CLI 成功退出也不能替代构建、类型检查和界面验证。
