# 品牌色选择

仅在创建新项目、配置现有项目，或用户提示词提到主题色时读取。

## 默认品牌色

项目默认品牌色是 `#0BA5EC`，已经作为 `--color-brand-*` 写入 CLI 内嵌的 `theme.css`。用户没有指定颜色时，不要传 `-c/--color`，也不要要求用户选择颜色，直接使用默认值。

## 优先级

品牌色属于用户明确要求与设计系统基线，优先级高于任何设计参与者提出的视觉方案：

- 用户提示词指定了颜色，或未指定而使用默认品牌色时，该值即为最终值，不再作为设计议题讨论。
- `impeccable` 或其他设计参与者不得替换、调整或重新生成品牌色，也不得引入平行色板或近似色。
- 设计流程认为品牌色不适配时，只能提出建议并交回用户确认，不能自行改色。
- 页面内色彩只能使用该品牌色阶与既有 semantic token，不得为追求视觉效果另建配色体系。

## 传入规则

按用户提示词里的颜色意图决定是否传参：

| 用户提示词 | 动作 |
| --- | --- |
| 没有提到颜色 | 不传 `-c`，使用默认品牌色 |
| 提到明确颜色词 | 解析为下表色族名，传 `-c <name>` |
| 提到颜色但无法对应 | 不传 `-c`，使用默认品牌色，并在交付说明中写明使用了默认色 |

不要把颜色词换算成十六进制，也不要新增 CLI 不支持的色名。CLI 收到未知色名时会保留默认品牌色，并在标准错误中输出警告。

## 支持的颜色

```text
brand（默认）、blue、indigo、violet、purple、fuchsia、pink、rose、orange、amber、yellow、green、teal、cyan、moss、red、gray
```

## 使用示例

```sh
untitled-cli init my-app --nextjs -c blue
untitled-cli init my-app --vite -c 藏青
untitled-cli init my-app --nextjs
```

## 边界

- `-c/--color` 只替换 `--color-brand-*` 语义 token，组件跟随变量变化，不修改组件源码。
- `--colors-list` 是本机交互式选择流程，Agent 场景不要使用，避免阻塞任务。
- 颜色无法对应时保持默认品牌色即可，不要中断项目创建，也不要自行扩展色板。
- 修改既有项目的主题色属于设计系统变更，需按设计系统契约取得用户确认。
